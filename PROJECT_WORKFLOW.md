# New project workflow

Start every new website, app, or game in its own GitHub repository under the project’s name. Store the current source, assets, setup notes, and deployment instructions there from the first build. Keep the repository public when the project is meant to be shared publicly and no private material is included.

Build and review the project, publish it from its repository where practical, then add its verified public URL to the right destinations: Salt & Light Web Studio portfolio, Light & Life Games, or a ministry site. Keep the link and preview current as the project evolves.

Give every public launch a distinct 1200 × 630 share image and matching Open Graph and X/Twitter metadata. Check that the image URL loads publicly and that chat previews show the intended title, description, and image. Use the same finished artwork for relevant portfolio cards, and update the hub’s game count from its actual cards.

## Required launch checklist

Every new public project ships as one coordinated update:

1. Create or update its own public repository and publish the working build.
2. Add a distinct 1200 × 630 share image plus a square favicon/app icon.
3. Add an accurate page title, description, canonical Open Graph URL, absolute Open Graph image URL, and matching X/Twitter card metadata.
4. Add the verified live project to Salt & Light Web Studio’s selected work.
5. If it is a game, add it to Light & Life Games and let the catalog count derive from the actual cards.
6. Add the C4 footer only to projects owned by Mike or Salt & Light.
7. Update the master project tracker with the repository, live URL, status, and launch notes.
8. Verify the live project, portfolio card, catalog card, artwork, description, direct links, count, and phone/desktop layouts after deployment.

Treat the project, catalog, portfolio, social preview, and tracker as one release. A launch is not complete until every applicable destination is updated and checked.
